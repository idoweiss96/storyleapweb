# משחקים — Games

התיקייה הזו מכילה את משחקי התפקידים של StoryLeap — משחקי "בוא נגיד ש…"
שילדים משחקים בהם בשביל הכיף, בלי מטרה טיפולית מוצהרת.

היא **אחות** ל-`src/components/activities/`, לא חלק ממנה. ראו "מה ההבדל" למטה.

---

## העיקרון המנחה

זהה לזה של הפעילויות. כל משחק כאן חייב לעמוד בשלושת התנאים:

| תנאי | למה |
|---|---|
| **אפס קריאות AI** | המשחק לא שולח בקשה לשום מודל, לא בטעינה ולא תוך כדי משחק |
| **אפס backend** | אין קריאות רשת, אין entities, אין functions. הכול רץ בדפדפן |
| **תוכן כתוב מראש** | כל טקסט, כל מטופל וכל הזמנה נכתבו ידנית לקובץ תוכן ונשמרים בגיט |

התוצאה: המשחקים עובדים אופליין, לא עולים כסף לכל שימוש, ולא נשברים
כשמודל מתעדכן. אותה סדרת לחיצות תמיד נותנת אותה תוצאה.

**אין ניקוד, אין טיימר ואי אפשר להפסיד.** בחירה לא נכונה מקבלת משפט רך
("זה לא מה שאני צריך עכשיו") ולא עונש. זה מכוון: הקהל שלנו כולל ילדים
שנרתעים ממשחקים שאפשר להיכשל בהם.

## מה ההבדל מ-`activities/`

| | `activities/` | `games/` |
|---|---|---|
| מקור | `StoryLeap_Professional_Tools_Map_v2` — 60 כלים מקצועיים | משחקי תפקידים קלאסיים לגיל הרך |
| מטרה | כלי טיפולי עם שאלה מוגדרת ("מה אני מרגיש?") | משחק חופשי |
| פלט | לרוב משהו להדפיס ולתלות | מה שקורה על המסך |
| מדידה | נגזר מאשכולות טיפוליים | לא רלוונטי |

כשמוסיפים דבר חדש שווה לשאול לאיזו משתי התיקיות הוא שייך. אם יש לו
**שאלה טיפולית מוגדרת** — הוא פעילות. אם הוא בעיקר **תרחיש לשחק בו** — הוא משחק.

`actions/` הוא הגבול המטושטש: הוא משחק, אבל נבנה סביב תרגול פעלים.
הוא נשאר כאן כי הילד משחק בו, לא מתאמן בו.

## על המקוריות של המימושים

המשחקים כאן נכתבו **מאפס**. הם שואבים השראה מז'אנר מוכר של משחקי תפקידים
לגיל הרך — מרפאה, פיצרייה, מוסך, חנות — אבל אין בהם שום קוד, איור, דמות
או שם מיובאים.

מכניקה של משחק היא רעיון ואינה מוגנת. שם, דמות ואיור כן. לכן:

- **אין** שימוש בשם של אף אפליקציה קיימת, לא בקוד ולא בשיווק
- **אין** דמות מועתקת. הדמויות הן אמוג'י סטנדרטי, או — במקרה של `actions/` —
  יצור שמצויר ב-CSS בתוך הרכיב עצמו
- **אין** אסט חיצוני בכלל. כל הגרפיקה היא CSS, SVG inline ואמוג'י

הכלל בהמשך: אם משחק חדש דורש להוריד קובץ מאפליקציה קיימת — הוא לא נכנס לכאן.

## מה קיים כרגע

| משחק | תיקייה | נתיב | הפעולה המרכזית |
|---|---|---|---|
| הקליניקה שלי | `clinic/` | `/games/clinic` | להתאים כלי לבקשה |
| הפיצרייה | `pizzeria/` | `/games/pizzeria` | להרכיב ולעבור רצף שלבים |
| המוסך | `garage/` | `/games/garage` | להתאים כלי לתקלה, ואז לצבוע |
| החנות | `store/` | `/games/store` | לבחור, לספור ולשלם — בשניים |
| מה טופי עושה? | `actions/` | `/games/actions` | ללחוץ על פועל ולראות אותו קורה |

**גיוון הפעולה נשמר בכוונה,** כמו ב-`activities/`. הקליניקה והמוסך חולקים
מנוע התאמה (כלי ↔ בעיה) אבל נבדלים במה שקורה אחריו: הקליניקה היא רצף
מחייב, המוסך הוא סט פתוח ואז צביעה. הפיצרייה היא היחידה עם **שלבים
בלתי הפיכים** (תנור → חיתוך → הגשה), החנות היחידה **לשני שחקנים**,
ו-`actions` היחיד שבו הילד לא בונה כלום — הוא רק גורם לדבר לקרות.

כשמוסיפים משחק, שווה לשאול לא רק "איזה תרחיש חסר" אלא **"איזו פעולה חסרה"**.

## מבנה התיקיות

```
src/components/games/
├── README.md                   ← הקובץ הזה
├── clinic/
│   ├── clinicContent.js        ← כל התוכן: כלים, מטופלים, UI, META
│   └── Clinic.jsx              ← הרכיב
├── pizzeria/
│   ├── pizzeriaContent.js
│   └── Pizzeria.jsx
├── garage/
│   ├── garageContent.js
│   └── Garage.jsx
├── store/
│   ├── storeContent.js
│   └── Store.jsx
└── actions/
    ├── actionsContent.js
    └── Actions.jsx
```

אין כאן `shared/`, **בכוונה**. הקליניקה והמוסך חולקים תבנית של "רשת כלים",
אבל שני מימושים הם לא מנוע — הם צירוף מקרים. הכלל מ-`activities/README.md`
תקף גם כאן: שכבה משותפת נגזרת משלושה מימושים אמיתיים, לא משניים.

הרכיבים יושבים כאן. **העמודים** יושבים ב-`src/pages/` והם דקים בכוונה —
כותרת, קישור חזרה, טיפ להורה, והרכיב עצמו.

## ארבע נקודות החיווט

כל משחק מחובר לאתר בארבעה מקומות. חשוב לעבור על כולם, אחרת המשחק קיים אבל לא נגיש:

1. **`src/components/games/<שם>/`** — הרכיב וקובץ התוכן
2. **`src/pages/Game<שם>.jsx`** — עמוד דק שעוטף את הרכיב
3. **`src/App.jsx`** — `import` + `<Route path="/games/<שם>" …>`
4. **`src/pages/Games.jsx`** — רשומה במערך `GAMES`, כדי שהכרטיס יופיע ב-hub

> `src/pages.config.js` הוא קובץ שנוצר אוטומטית. **לא נוגעים בו** — הנתיבים
> מוגדרים ידנית ב-`App.jsx`, כמו שאר הנתיבים המותאמים באתר.

## איך מוסיפים משחק חדש

### 1. קובץ תוכן

`src/components/games/<שם>/<שם>Content.js`. שלושה ייצואים קבועים, בדיוק
כמו בפעילויות:

```js
export const DECK = [ … ];                  // הנתונים (מטופלים, תוספות, פריטים)
export const UI = { he: {…}, en: {…} };     // כל מחרוזת שמוצגת למשתמש
export const META = { he: {…}, en: {…} };   // title + description ל-SEO
```

כל פריט נושא את הטקסט שלו בשתי השפות, כדי שהוספת פריט תהיה שינוי במקום אחד:

```js
{
  id: 'bear',
  emoji: '🐻',
  he: { name: 'דובי', problem: 'נפלתי מהעץ' },
  en: { name: 'Bruno', problem: 'I fell out of the tree' },
}
```

### 2. הרכיב

מקבל `lang` כ-prop (`'he'` או `'en'`) — הוא לא קורא ל-`useLanguage` בעצמו.
זה משאיר אותו נקי מהקשר וקל לבדיקה.

```jsx
export default function MyGame({ lang = 'he' }) {
  const copy = UI[lang] || UI.he;
  …
}
```

ה-CSS יושב ב-`const STYLE` בראש הקובץ ומוזרק ב-`<style>{STYLE}</style>`,
עם קידומת מחלקה קצרה וייחודית לכל משחק (`.cl`, `.pz`, `.gr`, `.st`, `.ac`).

### 3. העמוד

העמוד הוא זה שקורא ל-`useLanguage` ומעביר את התוצאה פנימה. העתיקו את
`src/pages/GameClinic.jsx` — הוא התבנית.

### 4. חיווט

`App.jsx` + `GAMES` ב-`Games.jsx`. ראו למעלה.

## קונבנציות

### שפה

דו-לשוני תמיד, עמוד אחד לשתי השפות. מתג השפה בהדר מחליף בין `he` ל-`en`
ללא ניווט. ה-RTL מטופל ברמת ה-`Layout`, אז אין צורך ב-`dir` ברכיב — אבל
**כן** צריך `inset-inline-start/end` במקום `left/right` לכל מיקום אבסולוטי.

### עיצוב

הפלטה של המותג, זהה לפעילויות:

| תפקיד | ערך |
|---|---|
| ורוד | `#FF6FB5` |
| תכלת | `#4FC3E8` |
| כחול כהה (טקסט/כותרות) | `#1A1A6E` |
| גבול רך | `#EDE9F8` |
| ורוד רקע | `#FFF0F7` / `#FFD6EC` |
| גרדיאנט כפתור ראשי | `linear-gradient(135deg, #FF6FB5, #4FC3E8)` |

הטיפ להורה בסוף כל משחק משתמש בסכמה הצהובה (`#FFF8EC` / `#F5C842` / `#7A5000`).

### נגישות

- `aria-pressed` על כל דבר שנבחר
- `aria-live="polite"` על אזור שמתעדכן אחרי פעולה (מה הדמות אומרת, הסכום בקופה)
- `prefers-reduced-motion` — כל אנימציה חייבת מסלול חלופי בלי תנועה.
  זה קריטי כאן יותר מאשר בפעילויות, כי המשחקים מונפשים הרבה יותר
- מטרות מגע של 44px ומעלה
- `role="img"` + `aria-label` על אמוג'י שנושא משמעות; `aria-hidden` על אמוג'י דקורטיבי

### הדפסה

המשחקים כאן **לא** מייצרים פלט להדפסה — כל כולם מה שקורה על המסך בזמן אמת,
כמו הטיימר והנשימות ב-`activities/`. עדיין מסמנים `site-chrome` על כפתורים
וקישורים, כדי לשמור על עקביות עם שאר האתר.

### קול

`actions/` משתמש ב-`window.speechSynthesis` כדי להקריא את הפועל. זה API
מובנה בדפדפן — **לא** קריאת רשת ולא שירות חיצוני, ולכן הוא לא מפר את
העיקרון של אפס backend. הוא כבוי כברירת מחדל, ואם למכשיר אין קול בשפה
המבוקשת הוא פשוט שותק.
