# shared — השכבה המשותפת לפעילויות הכרטיסים

הקלף, ה-CSS שלו, שדה התשובה שיודע להידפס, וסרגל הפעולות.
כל פעילות שמבוססת כרטיסים בונה על השכבה הזו במקום לשכפל אותה.

---

## למה זה נוצר רק עכשיו

השכבה הזו **לא** נבנתה עם הפעילות הראשונה, ובכוונה.

לפי מיפוי 60 הכלים, מנוע הכרטיסים פותח 6 מכלי גל 0 ו-12 מתוך כל 60 —
ולכן היה מפתה להפשיט אותו מיד. אבל מנוע שנגזר ממימוש **אחד** הוא ניחוש
לגבי מה יחזור, ולרוב מייצר הפשטה שצריך להילחם בה אחר כך.

במקום זה חיכינו לשלושה מימושים שונים באמת:

| פעילות | מצב | מה הילד עושה |
|---|---|---|
| גלגל הרגשות | `spin` | מקבל קלף אקראי |
| קלפי החוזקות | `pick` | בוחר קלפים שמתארים אותו |
| הקלפים שעוזרים לי | `build-a-kit` | בוחר קלפים ובונה מהם ערכה |

רק אז היה ברור מה באמת משותף — ומה רק *נראה* משותף.

---

## מה משותף, ומה לא

**עבר לשכבה המשותפת** (חזר בכל שלושת המימושים):

- מראה הקלף — פרופורציה, מסגרת פנימית, סמלי פינה, צל, מצב נבחר
- קלף התוצאה — מסגרת, כותרת, קו מפריד, גוף
- שדה התשובה שמתנהג נכון בהדפסה
- סרגל "לבחור מחדש / להדפיס"
- בחירת צורת הרבים למונה

**נשאר בכל פעילות** (היה שונה בכל אחת):

- התוכן — טריוויאלית
- מה קורה בלחיצה — בחירה מרובה מול סיבוב אקראי
- מה נכנס לקלף התוצאה — שאלה, הוראה, או כלום
- תוספות ייחודיות — למשל שדה "משהו אחר שעוזר לי" ב-Coping Cards

הכלל שהנחה את החלוקה: **הצורה משותפת, ההתנהגות לא.**

## הקבצים

| קובץ | תוכן |
|---|---|
| `cardStyles.js` | `CARD_STYLES` — הקלפים · `ANSWER_STYLES` — שדה התשובה |
| `ActivityCards.jsx` | `PickerCard`, `ResultCard`, `PrintableAnswer`, `ActionBar`, `Pips`, `countLabel` |

### למה ה-CSS מפוצל לשניים

גלגל הרגשות צריך את שדה התשובה אבל **לא** את חפיסת הקלפים —
קלף התוצאה שלו הוא תיבה משלו, צבועה לפי הרגש שיצא.
ייבוא של `CARD_STYLES` שם היה מזריק לדף עשרות כללים שאף אחד לא משתמש בהם.

```js
// פעילות כרטיסים מלאה
<style>{CARD_STYLES + ANSWER_STYLES}</style>

// גלגל הרגשות — רק השדה
<style>{ANSWER_STYLES}</style>
```

## שימוש

כל פעילות עוטפת את עצמה ב-`.ac-deck`, שהוא התחום של כל ה-CSS כאן:

```jsx
import { CARD_STYLES, ANSWER_STYLES } from '../shared/cardStyles';
import { ActionBar, PickerCard, PrintableAnswer, ResultCard, countLabel } from '../shared/ActivityCards';

<div className="ac-deck">
  <style>{CARD_STYLES + ANSWER_STYLES}</style>

  {/* חפיסת הבחירה */}
  <div className="grid grid-cols-2 sm:grid-cols-3 md:grid-cols-4 gap-3 md:gap-4">
    {DECK.map((item) => (
      <PickerCard key={item.id} emoji={item.emoji} label={item.label}
                  selected={…} onClick={…} />
    ))}
  </div>

  {/* מסך התוצאה */}
  <div className="ac-result-grid">
    <ResultCard emoji={item.emoji} title={item.label} body={item.prompt}>
      <PrintableAnswer value={…} onChange={…} placeholder={…} ariaLabel={…} />
    </ResultCard>
  </div>

  <ActionBar onRestart={…} restartLabel={…} onPrint={() => window.print()} printLabel={…} />
</div>
```

`ResultCard` מקבל `children`, ולכן פעילות שלא צריכה שדה תשובה
(כמו Coping Cards, שבו הקלף נושא הוראה ולא שאלה) פשוט לא מעבירה כלום.

## מה גורם לקלף להיראות כמו קלף

| פרט | מימוש |
|---|---|
| פרופורציה | `aspect-ratio: 5/7` — יחס של קלף משחק |
| מסגרת פנימית | `::before` עם `inset: 7px` — קו דק בתוך השוליים, כמו בקלף מודפס |
| סמלי פינה | ✦ למעלה-התחלה ולמטה-סוף, השני מסובב `180deg` כמו אינדקס בקלף |
| עומק | צל כפול, והקלף מתרומם ומסתובב `-1deg` בריחוף |
| מצב נבחר | מתרומם `-6px`, גרדיאנט ורוד, מסגרת `#FF6FB5`, צ'ק כחול על הפינה |

קלף התוצאה (`.ac-bigcard`) שומר על אותם פרטים, אבל בלי `aspect-ratio` קבוע —
הוא גדל לפי אורך התוכן. הפריסה שלו היא שתי עמודות, גם במסך וגם בהדפסה,
כדי שההדפסה תיראה כמו סט קלפים ולא כמו טופס.

## `PrintableAnswer` — למה זה לא סתם textarea

דפדפנים **חותכים** טקסט שגולש מעבר לגובה הנראה של `textarea` בהדפסה,
כך שתשובה ארוכה הייתה מודפסת חלקית. לכן הרכיב מרנדר שלושה דברים:

1. `textarea` — נראה במסך, מוסתר בהדפסה
2. פסקה עם הטקסט שנכתב — מוסתרת במסך, נראית בהדפסה, נפרשת לגובה המלא
3. שורות מקווקוות — נראות בהדפסה **רק** כשהשדה ריק

הפריט השלישי הוא מה שנותן שני מסלולי שימוש מאותו מסך: למלא במסך ולהדפיס
מוכן, או להדפיס ריק ולמלא בעיפרון. ילד שעוד לא מקליד מקבל דף עבודה.

מספר השורות נשלט ב-`lines` (ברירת מחדל 3).

## RTL

כל מיקום אבסולוטי כאן משתמש ב-`inset-inline-start/end` ולא ב-`left/right`.
בלי זה סמלי הפינה והצ'ק היו קופצים לצד הלא נכון במעבר בין עברית לאנגלית.

זו הטעות הקלה ביותר לעשות בתוספת עתידית לקובץ הזה — שווה לבדוק
כל כלל חדש גם באנגלית לפני שסוגרים.
