# משחקי חשיבה ולמידה — Learning Games

תשעה משחקים תלת-ממדיים לגילאי 3–11. בכל אחד יש **שחקן שזז בעולם, דמויות NPC
ופעולות** — ובכל אחד המכניקה נבחרה כי יש מחקר שמראה שהיא מאמנת מיומנות מסוימת.
הלמידה היא המשחק עצמו, לא חידון שהודבק עליו.

אחות ל-`src/components/games/` (משחקי התפקידים הדו-ממדיים): אותם עקרונות,
אותה פלטה ואותן חיות, אבל עולם תלת-ממדי.

## העקרונות

- **אפס AI, אפס backend.** הכול רץ בדפדפן. אין entities, אין functions.
- **תוכן כתוב מראש** בקבצי `*Content.js`, בעברית ובאנגלית.
- **אין טיימר ואי אפשר להפסיד.** טעות מקבלת משפט רך וצליל שקט (`hmm()`), אף פעם לא זמזם.
- **אין קבצי מודל, תמונה או קול.** כל דמות וחפץ בנויים מפרימיטיבים של Three.js;
  הצלילים מסונתזים ב-Web Audio והמילים ב-`speechSynthesis`.
- **המכניקות לקוחות מהמחקר ומז'אנרים ותיקים**, לא מאפליקציה מסוימת. אין שם,
  דמות או איור של מוצר קיים.

### פרטים שחשוב לא לשבור

- **אבני הנהר**: האבנים בקו **ישר משמאל לימין**, וכל אבן שנוחתים עליה אומרת
  **את המספר שלה**. אלה שני הרכיבים שעשו את ההבדל במחקר. פס 1…N קבוע בראש
  המסך, כי המצלמה רואה רק כמה אבנים בכל פעם.
- **הדוור**: רק הבית הראשון והאחרון מסומנים. פס 0…max בראש המסך מחזיק את
  שני הקצוות בעין — הערכה דורשת לראות אותם.
- **יום הפוך**: בלי טיימר בכוונה. לחץ זמן הופך משחק עיכוב למשחק תסכול.
- **מצעד התופים**: מספר ההברות נגזר מ-`parts.length`, אף פעם לא נכתב בנפרד.
- **dwell על משטחים צמודים**: בקופסאות, בארגזים, אצל הנגנים ובחלקי הבנייה,
  משטח נספר רק אחרי עמידה של רגע. ילד שרץ לנגן השלישי עובר דרך השני —
  וזה לא אמור להיחשב. זה ב-`engine.pad({ dwell })`.

## מבנה

```
learning-games/
├── registry.jsx             ← הרישום היחיד: routes + כרטיסים נגזרים ממנו
├── LearningGamePage.jsx     ← עמוד אחד לכל המשחקים (כותרת, משחק, טיפ, "למה זה עוזר")
├── LearningGamesSection.jsx ← הבלוק ב-/games
├── world3d/                 ← המנוע המשותף
│   ├── engine.js            ← class World: רנדרר, שחקן, מצלמה, משטחים, NPC, tweens, חץ מנחה
│   ├── WorldView.jsx        ← המסגרת ב-React: רמות, מסך פתיחה/סיום, HUD, רמז, מספרים צפים
│   ├── models.js            ← דמויות (החיות של האתר בתלת-ממד), פירות, מטבעות, טבעות, חץ
│   ├── props.js             ← נוף: עצים, בתים, נהר, אבנים, תוף, קופסאות, רכבת, במה
│   ├── cards.js             ← מצייר ציורי SVG של האתר על שלטים וקלפים בעולם
│   └── input.js             ← ג'ויסטיק צף + חצים/WASD
├── shared/                  ← GameShell (סגנונות, בורר רמות, צליל), LearnArt, sound.js
└── <game>/ <game>Content.js + <game>World(.js|.jsx) + <Game>.jsx
```

`fruit-stand/` נבנה ראשון ויש לו לולאה משלו ב-`game.js`; הוא משתמש ב-`world3d/models`
וב-`world3d/input`. שאר המשחקים יורשים מ-`World`.

### איך בונים משחק חדש

1. `xContent.js` — `LEVELS`, `UI {he,en}`, `META`.
2. `xWorld.js` — `class XWorld extends World` עם `build()` (הסצנה), `tick(dt,t)`
   (החוקים), `hint()` (שורת ההנחיה), `snapshot()` (מה React צריך).
   קובץ שמכיל JSX (בשביל `cards.js`) חייב סיומת `.jsx`.
3. `X.jsx` — `<WorldView GameClass={XWorld} … />`, עם `hud`, `actions` ו-`renderOverlay` לפי הצורך.
4. רשומה ב-`registry.jsx`.

אלמנט ב-overlay עם `data-anchor="id"` נצמד בכל פריים למיקום שהמשחק מחזיר ב-`anchor(id)`.

## חיווט

משחק חדש = רשומה ב-`registry.jsx`. `App.jsx` ממפה את הרשימה ל-routes,
ו-`Games.jsx` מציג את `LearningGamesSection`. העמוד **לא** יושב ב-`src/pages/`
בכוונה — קבצים שם נרשמים אוטומטית ב-`pages.config.js`.

Three.js הוא תלות קיימת של האתר. כל משחק נטען כ-chunk נפרד רק בעמוד שלו.

## בדיקות

`window.__LG_DEBUG` חושף את המשחק (`window.__world`, ובדוכן `window.__fruitStand`)
לבוט בדיקה שמשחק כל משחק עד הסוף בדפדפן. האתר אף פעם לא מגדיר את הדגל.
בלי WebGL מוצגת הודעה במקום קופסה ריקה.

## המרחב של הילד

ה-`slug` הוא המקטע האחרון בנתיב — אותה מוסכמה ש-`ActivityFeed` משתמש בה
כדי לזהות פעילות שמורה. כשנרצה להכניס את המשחקים למרחב, אין צורך במפתח חדש.
